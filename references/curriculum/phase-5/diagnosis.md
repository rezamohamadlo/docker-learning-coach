# Diagnose from evidence

## Previous-note recap

Recall: Recreation and persisted state. Connect that distinction to today’s observation.

## Mental model

Start with the symptom and a falsifiable hypothesis. Check state, logs, published ports, process binding, mounts and network names as needed. A successful build does not prove the app is reachable.

## Guided practice

Use the Lab 05 failure drills. Change one factor at a time and retain the command output that distinguishes hypotheses.

## Independent evidence

Given a reachable host port with a 503 response, choose an application/dependency check before rebuilding everything.

The coach should vary the assessment after guided practice. Explain your prediction before running a check; preserve actual output when runtime behavior is part of the outcome.

## Summary

Start with the symptom and a falsifiable hypothesis.
